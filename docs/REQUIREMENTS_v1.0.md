# AI FILE QUEST｜思想・要件定義 Ver.1.0 FIX
## 要点
- プレイヤーがAIエージェント役として、ユーザーのチャット指示を受け、仮想フォルダ内の指示・資料を実際に開いて読んで成果物を作るゲーム。
- Claude Code風ダークテーマの3カラムUI。全10ステージ構想、初期MVPは3ステージ、実際のAIの作業工程と遊びやすさを両立。
- Ver.1.0要件はFIX済み。開発は未着手。詳細設計・実装は別途指示を受けてから。
想定する使い道：Claude Codeへの企画引き継ぎ／ゲーム詳細設計／MVP開発判断。

## 1. 背景・発想・思想
出発点はGitHubリポジトリ「iwatsuyo0719-byte/AI-COMMAND-CENTER」の実際のフォルダ階層を図解したこと。ユーザーは、AIが膨大なファイルから人間の指示に必要な情報を探し出す過程を、自分自身がAIになって体験できるゲームを着想した。

根本思想：
- 「AIの活動を外から眺めるゲーム」ではなく、「プレイヤー自身がAIとして仕事をするゲーム」。
- ユーザーのチャット依頼を受信し、左側の実際のツリーでフォルダを開き、AGENTS.mdやCLAUDE.md、README.md、CSV、テンプレートなどを読み、指示・根拠・制約を確認し、成果物を提出する。
- 単なる情報発見パズルにしない。正しいファイルの探索、指示の遵守、古い/矛盾する情報の検証、出典の裏付け、適切な出力をゲーム性にする。
- 実際のAIエージェントの外部から観察可能な仕事の流れ（指示解釈→探索→読解→検証→生成・提出）をモデル化する。モデル内部の非公開推論過程の忠実な再現を謳わない。
- ステージの進行で、フォルダ構成、指示の複雑さ、成果物、操作機能・権限を段階的に拡張する。
- 現実味を持たせつつゲームとして遊びやすくする。「リアルさとゲーム性の両立」を選択。
- 初期投資・規模を小さくし、MVPで核となる体験を先に検証する。

## 2. 決定履歴（確定）
- ゲーム名（仮）：AI FILE QUEST。
- D案「フォルダ探索・指示理解・成果物作成のハイブリッド」。
- 成果物方式B：情報収集・証拠の組み立て。さらに成長方式C：初級は穴埋め、中級はカード配置、上級は複合編集。
- UI：Claude Codeデスクトップアプリを参考にした**ダークテーマ**、3カラム。左=ファイルツリー、中央=ファイルエディター（将来ターミナル）、右=チャット依頼・証拠・成果物・提出。グレー基調、テラコッタ系アクセント。初期案にあったライト系配色は最終仕様ではない。
- ファイル操作権限C：閲覧→新規作成→既存ファイル編集を段階解放。
- 探索操作C：GUIから始めて検索・疑似ターミナルのコマンドを段階解放。後半でもGUIでのクリア経路を残す。
- リアルさB：AI業務再現とゲーム性の両立。
- 制限時間なし＋探索効率で採点。
- ステージは順番に解放、クリア済みは何度でも再挑戦、最高スコアを保存。
- セーブ：最高スコアと解放状態のみlocalStorageへ保存。途中セーブなし。リトライ時はステージ内の状態を初期化。アカウント不要。
- 全体構想10ステージ、MVPは最初の3ステージ。
- MVP完成判定は後述の5条件。
- 要件定義 Ver.1.0 FIX（2026-10-17）。**まだ開発しない**。GitHubへのゲーム専用リポジトリ作成、コード実装、デザイン生成も未承認。

## 3. ゲーム基本フロー
1. ユーザーからチャット依頼を受け取る。
2. ファイルツリーをクリックしてフォルダを展開し、対象ファイルを開く。
3. AGENTS.md等の適用指示、README、資料、テンプレートを実際に読む。
4. 必要な情報を証拠（出典付き）として収集し、他のファイルと照合する。
5. ステージの方式に従い穴埋め／カード配置／複合編集により成果物を作る。
6. 提出すると正確性・網羅性・指示遵守/根拠・効率で採点され、解説・探索履歴・改善点を表示する。
7. 規定点で次のステージを解放。再挑戦可能。

## 4. UI / 操作
- PCブラウザ向け。デスクトップIDE風ダークテーマ。
- 左カラム：仮想フォルダツリー。クリックで開閉、ファイル選択。
- 中央：選択したmd/txt/csvを実際に表示・閲覧し、必要な箇所を選択して証拠化。将来は下部に折りたたみ型ターミナル。
- 右：ユーザー依頼、ステージ条件、収集した根拠、組み立て中の成果物、提出操作。
- 初級はGUIのみ。中級でファイル名検索およびpwd,ls,cat等を追加。上級でfind,grep,全文検索・編集機能を追加する構想。
- ターミナルは安全な疑似環境で、実OSコマンドやユーザーPCの実ファイルを実行・変更しない。

## 5. 仮想ファイル・指示の考え方
- ゲーム内に実データを持つ仮想ファイルシステムを実装する。単なる飾りのフォルダではない。
- 初期ファイル形式：.md、.txt、.csv。
- AGENTS.mdやCLAUDE.mdなどが作業指示ファイルとして登場し、内容の遵守が採点へ反映される。実際のClaude Code等での読み込み仕様とゲーム内のルール体系は同一とは限らず、適用範囲・優先順位はゲーム内で明示する。
- 資料・出典・テンプレート・決定事項・古いデータ等を必要に応じて配置する。
- 表示するファイル本文と、システム側の正答・評価データは分離する。
- 重要：ファイルを開いた事実のみでは満点にせず、ルールを成果物に反映できたかを評価する。
- 元になったGitHubリポジトリのフォルダ構成は着想の参考に留める。MVPでは架空データ。実GitHubやローカルファイルとのライブ連携なし。

## 6. ステージ設計（10ステージ構想）
1. ファイルを探せ：単一資料から指定情報を特定、穴埋め一文回答。
2. AIのルールを守れ：AGENTS.mdに基づき条件付き回答。
3. 複数資料を照合せよ：複数ファイルから売上比較表。
4. 多数ファイルから必要資料を特定：検索・基本コマンド解放。
5. 月次レポートを作成・保存：テンプレート・ファイル/フォルダ作成。
6. 曖昧な依頼への対応：不足情報の判断。
7. 古い資料・新しい資料の矛盾を解決：高度な検索、全文検索。
8. 既存資料を指示通り修正：編集権限・変更管理。
9. 複数成果物を作成：複数タスク管理。
10. 総合AIエージェント業務：複雑な指示、根拠、作成を統合。
人数・ファイル数・具体的難度配分は仮案で、テストプレイ後に調整。初級（1-3）閲覧・GUI、中級（4-6）検索・作成、上級（7-10）全文検索・編集という大枠。

## 7. MVP（ステージ1〜3）
### Stage 01 ファイルを探せ
依頼例：「9月の売上金額を教えてください。」
WORKSPACE/README.md、DATA/august.csv、DATA/september.csv、NOTES/memo.md等を配置。
ユーザーがDATA/september.csvを実際に開き、該当する金額を発見して回答。フォルダ探索を学ぶ。

### Stage 02 AIのルールを守れ
依頼例：「社内ルールに従って先月の売上を回答してください。」
WORKSPACE/AGENTS.md、README.md、DATA/sales_august.csv、DATA/sales_september.csv、RULES/accounting.md等。
指示ファイルを実際に開き、指定の表記条件（例：税抜き）や参照先を守り、根拠付きの回答を提出。基準年月をステージデータで明示して「先月」の曖昧さを排除する。

### Stage 03 複数資料を照合せよ
依頼例：「8月と9月の売上を比較し、増減額と増減率をまとめてください。」
WORKSPACE/AGENTS.md、DATA/august.csv、DATA/september.csv、DATA/notes.md、REFERENCES/glossary.md、TEMPLATES/comparison.md等。
複数ファイルから証拠を収集し、数値を照合し、比較表を組み立てて提出。

MVPには「フォルダ開閉、ファイル表示、指示読解、証拠保存、成果物の穴埋め・カード配置、自動採点、ヒント、ステージ解放、最高点保存、リトライ」を含む。ターミナル、外部LLM API、実GitHub同期、実OS編集、ファイル作成・編集は含めない。

## 8. 得点・クリア・効率
100点満点：
- 正確性：40点
- 網羅性：25点
- 根拠・指示遵守：20点
- 探索効率：15点
ランク：S=90〜100、A=80〜89、B=70〜79、C=0〜69。70点以上でクリア、次ステージ解放。重大な捏造・禁止操作は点数にかかわらず不合格とする構想。
制限時間なし。
探索効率は不要なファイル閲覧や反復操作などを対象とするが、ルール確認、合理的な探索・検証は減点しない。効率配点上限15点のため試行錯誤だけでクリア不能にならない。具体的な数式や減点係数は未FIX、詳細設計で決める。
情報が存在しない場合に「不明」と判断することも正解として評価できる設計。

## 9. ヒント・振り返り
- 段階的な3段階ヒント：考え方→探索対象→具体的手順。
- 結果画面：総得点、ランク、4項目の内訳、指示遵守、探索の振り返り、改善点。
- ヒント利用の減点条件は詳細設計で決める。初級では学習を阻害しないことを優先。

## 10. 保存・進行（最終決定）
- 順番にステージ解放。前ステージを70点以上でクリアすると次へ。
- クリア済みステージは無制限再挑戦。ステージ別最高スコア記録。
- localStorageへ「解放状態」と「最高スコア」のみ保存。
- 途中セーブなし。再挑戦ではステージ内の仮想ファイル/回答/収集証拠を初期状態に戻す。
- 登録・ログイン・クラウド同期はMVP対象外。

## 11. MVP完成の受け入れ条件（確定、5条件）
1. 3ステージすべてを最初から最後まで遊べる。
2. 実際にフォルダを開き、ファイルの内容を読める。
3. 指示ファイルの条件が正答判定に反映される。
4. 正解・不正解を判定し、採点結果を表示できる。
5. ステージ解放・最高点保存・リトライが正常に動作する。

## 12. 未FIX事項（詳細設計に委ねる）
- 仮想ファイルシステムの具体データ構造、表示・採点ロジックとの分離方式。
- ステージの実際のファイル本文、正答・誤答、指示ファイルの文言、採点テストデータ。
- 証拠選択と保存の操作細部、カード配置と提出フォームの詳細。
- 探索効率・ヒントの減点係数、重大違反の判定詳細。
- 画面遷移、レスポンシブ下限、技術スタック、UIコンポーネント設計。
- 各ステージの実際のプレイ時間や難易度の校正。

- まずユーザーから詳細設計または実装着手の明示的指示があるまでコード変更・リポジトリ作成・MVP着手をしない。
